## 0. Уже зафиксировано (на основе разговора)

| Параметр | Значение |
|----------|----------|
| Имя проекта | **O.S.A.** (Операционная Система Агента) |
| Цель | Уменьшить e-waste + получить дешёвый compute + маленькая LLM + сильный scaffolding = агент для больших задач |
| Тип проекта | Хобби |
| LLM на старте | Minimax (`MiniMax-M3`), есть ключ, квоты хватает |
| LLM в перспективе | Своя ~1B-модель, обучается параллельно на другом ПК |
| Стек MVP | Python 3.11+, SQLite, без LangChain/AutoGen |
| Скоуп MVP | Слой 1 (OSA Runtime): always-on агент в sandbox на одной машине |
| Что НЕ в MVP | Bare-metal (слой 2), Mesh (слой 3), UI в браузере, мультиагент, Telegram-бот |
| Главная фича | Агент автономен (ставит себе задачи, планирует, работает в фоне) |
| Формула успеха | Маленькая модель + сильный scaffolding решают задачи, которые сама модель без фреймворка не решает |

## 3. Стек и зависимости

- **Язык MVP**: Python 3.11+
- **Альтернатива рассмотрена**: TypeScript — отклонено (ML-экосистема нужна сразу, локальная работа с эмбеддингами)
- **Готовые библиотеки (must)**:
  - `pydantic` v2 — структурный вывод, конфиги, валидация
  - `httpx` — async HTTP к LLM API
  - `rich` + `typer` — CLI
  - `sqlmodel` или `peewee` — ORM для SQLite
  - `apscheduler` или своё — планировщик задач
  - `structlog` — структурное логирование
- **НЕ использовать**:
  - `langchain` — прячет промпты, дебажить ад
  - `autogen` / `crewai` — мультиагент не нужен на MVP
  - `llama-index` — RAG не критичен для MVP

## 5. Ключевые механики MVP

- [ ] Always-on runtime (демон / сервис, автоперезапуск)
- [ ] Цикл «think-act-observe» (ReAct)
- [ ] Инструменты (минимум): file read/write в sandbox, shell, http, web_search, time/date
- [ ] Планировщик отложенных задач («через час», «каждый день в 9:00»)
- [ ] Краткосрочная память (в контексте сессии)
- [ ] Долгосрочная память (SQLite, факты, события, заметки)
- [ ] Декомпозиция задач (большую разбивает на шаги)
- [ ] Итерации и рефлексия (попробовал — упал — попробовал иначе)
- [ ] Human-in-the-loop для опасных команд (подтверждение перед `rm`, перед внешними действиями)
- [ ] Логирование всех шагов (что думал, что делал, что получил)
- [ ] Лимит итераций на задачу (защита от runaway)
- [ ] Контроль расхода токенов (особенно пока Minimax платный)
- [ ] Graceful shutdown (Ctrl-C → корректно сохранить состояние)

## 6. Нефункциональные требования

- **Запуск**: `uv run osa start` (или `python -m osa`). CLI-команды: `start`, `status`, `task add`, `task list`, `logs`, `stop`.
- **Хранилище**: `$XDG_DATA_HOME/osa/` (на Windows = `%LOCALAPPDATA%/osa/`). Внутри:
  - `osa.db` — SQLite (память, задачи, логи)
  - `sandbox/` — рабочая папка агента (НЕ пользовательские файлы)
  - `logs/` — структурные логи
  - `config.toml` — настройки
- **Развёртывание MVP**: `git clone && uv sync && uv run osa init && uv run osa start`. Без Docker.

## 7. Ограничения и риски (приоритизированы)

| Риск | Вероятность | Митигация |
|------|-------------|-----------|
| Своя 1B-модель долго не готова | Высокая | Абстракция `LLMProvider`, два бэкенда |
| Runaway-агент жрёт ресурсы | Средняя | Лимит итераций, watchdogs, timeouts |
| Маленькая модель плохо tool-call'ит | Высокая | Парсинг JSON из текста + pydantic-валидация + retry |
| Minimax API изменится / кончится квота | Средняя | Локальный stub, лёгкая смена провайдера |
| Один разработчик, выгорание | Высокая | Чёткие MVP-критерии, без фич-кривой |
| Mesh-слой когда-нибудь задавит | Низкая сейчас | Зафиксировано в VISION как слой 3, не в скоупе MVP |
