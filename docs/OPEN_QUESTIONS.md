## 1. Что такое «OSA» в этой метафоре

- **Матка** (queen) — центральный goal-driven агент. На MVP живёт где? На одной ноде? На отдельной «главной» машине? Плавает между нодами?
- **Рабочие осы** (workers) — отдельные ноды в mesh, каждая со своим runtime, выполняют подзадачи
- **Соты** (cells) — единицы compute/памяти внутри одной ноды (или это слишком мелко?)
- **Гнездо** (hive) — mesh из всех нод вместе
- **Феромоны** (pheromones) — общая память/knowledge, к которым все ноды имеют доступ

**Что обсудить:**
- Кто королева? Одна выделенная нода или любая может быть?
- Если матка умерла — что происходит? Выбирается новая? Работа стоит?
- Рабочие осы могут самостоятельно ставить себе подзадачи или только по приказу матки?
- Сколько уровней иерархии: 1 (плоский mesh) / 2 (матка + рабочие) / 3 (матка + рабочие + суб-рабочие)?

## Решения

### 1. Матка — где живёт и что делает, если умерла

**Решено 23.09.2026**:
- **Матка = LLM-инстанс.** Не процесс, не нода, а именно инстанс модели. Бессмертна, пока инстанс существует (можно перезапустить на другой ноде — это не «смерть матки», это миграция инстанса).
- **Если инстанс умер (процесс LLM killed):** агенты (рабочие ноды) продолжают выполнять свои текущие задачи автономно, без центрального координирования. Никаких перевыборов, никакого нового «царя» — каждая нода просто дорабатывает то, что уже начала.
- **Новые задачи:** пока матка мертва — не берутся. Ноды ждут восстановления инстанса.
- **Из этого следует:** вся декомпозиция цели, планирование, выбор следующей задачи — это функция матки. Рабочие только исполняют. Это **разделение труда по функциям**, а не по иерархии.

**Архитектурные следствия**:
- Рабочая нода может работать автономно какое-то время без матки (выполнять ранее полученную задачу)
- Матка должна уметь мигрировать между нодами (привязка к железу недопустима)
- Состояние матки (план, контекст) должно реплицироваться на все ноды, чтобы при миграции не терялось
- «Матка умерла» — это operational problem, а не архитектурный. Восстановление через рестарт инстанса на любой ноде.

### 2. Что в MVP

**Решено 23.09.2026**:
- **MVP = голый runtime на этом ноуте** (одна нода, она же матка). Агент общается с Minimax API, пишет в SQLite, имеет CLI.
- **Цель MVP**: накопить наработки, провести бенчмарк «агент vs голая модель», доказать формулу «маленькая модель + scaffolding > голая модель».
- **Когда MVP готов**: переходим к bare-metal install и mesh.
- **LLM на MVP**: Minimax (уже есть ключ, проверена, квоты хватает). Своя 1B-модель подключается позже как замена/дополнение.

### 3. Trust-модель установки (красная линия)

**Решено 23.09.2026**:
- **OSA устанавливается ТОЛЬКО при физическом присутствии владельца устройства.** Это не опция, это базовый принцип архитектуры.
- **Каналы установки** (все требуют физического доступа):
  - USB-кабель / флешка / SD-карта — пользователь сам записывает образ
  - USB-debug на Android — пользователь сам подтверждает «Разрешить отладку» на экране
  - PXE / сетевая загрузка в локальной сети — пользователь сам настраивает DHCP/TFTP
  - Bare-metal install через ISO-образ — пользователь сам записывает и загружает
- **Что ЗАПРЕЩЕНО в принципе**:
  - Самораспространение по сети (черви)
  - Удалённая установка без явного действия владельца
  - Скрытая установка под видом других приложений
  - Auto-discovery чужих устройств в mesh
- **Trust-модель mesh**:
  - Каждая нода принадлежит владельцу и знает свой «рой» (список публичных ключей разрешённых нод)
  - Чужое устройство не может присоединиться без явного добавления владельцем (физически рядом с обеими нодами)
  - Trust = список fingerprint'ов, не сетевая репутация
- **Почему это фича, а не ограничение**:
  - Юридически чисто (не подпадает под определение ВПО)
  - Безопасно по умолчанию (нет вектора «твой телефон сам подцепил OSA от соседа»)
  - Можно публиковать на GitHub, использовать в компаниях/школах/энтузиастами
  - Использование старого железа как compute не требует самораспространения — люди сами приносят устройства
- **Пример пользовательского сценария** (Михаил с 4 смартфонами):
  1. Скачал APK/ISO OSA с официального сайта
  2. Подключил смартфон по USB к ноуту
  3. Подтвердил на экране смартфона «Разрешить установку»
  4. OSA переписала Android на свою прошивку (с подтверждением)
  5. Смартфон стал нодой гнезда
  6. Повторил для остальных 3
  7. Все 4 смартфона + ноут = гнездо, физический доступ был ко всем

### 4. Железо

**Решено 23.09.2026**:
- **Целевое железо для нод**: **любые устройства с возможностью подключения к интернету и проводной сети**. Список по приоритету:
  - Смартфоны с разбитым экраном (основной use case Михаила — 4 штуки)
  - Планшеты
  - Старые ноутбуки
  - Старые десктопы
  - Raspberry Pi и одноплатники (если есть)
  - Smart TV / TV-приставки (если есть смысл)
- **Базовое требование к ноде** (уточним в M1):
  - CPU: ARM или x86_64, любой
  - RAM: ≥512 МБ (для смартфонов с 1-2 ГБ)
  - Хранилище: ≥2 ГБ свободных
  - Сеть: Ethernet ИЛИ Wi-Fi (mesh — по проводу приоритетно)
  - Физический доступ для установки
- **В наличии сейчас у Михаила**: 4 смартфона с разбитым экраном + этот ноут (dev-машина). Для MVP хватит, для bare-metal-тестов — ноут, для смартфонов — когда будет готов APK.
